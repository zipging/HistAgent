# HistAgent availability investigation, September 6, 2026

The static website served successfully. Public GPU workflows were not restored
at the end of the initial repair because HF's edge still rejected gateway-to-
model traffic with HTTP 429. A passing `/api/health` response alone must not be
used as evidence of a completed inference request.

## Confirmed failures

1. The inference function requested 180 seconds. The deployed `spaces` 0.51.3
   SDK applies a duration factor of 1.5 on Blackwell, making the actual request
   270 seconds. The queue returned: `The requested GPU duration (270s) is larger
   than the maximum allowed`. This is a scheduler rejection before execution.
2. Gradio 5.44.1's simplified `/gradio_api/call` stream discarded the failed
   queue result's `output.error`, emitting an error event with `null`. This hid
   the scheduler error and prevented accurate reservation refunds.
3. HF's private-Space entrance intermittently returned an HTML HTTP 429 with
   `server: awselb/2.0` and no `Retry-After`. The failure occurs on `/config`,
   before any model work. A controlled comparison used the same OAuth token:
   local `/config` returned 200, while the gateway container returned 429. The
   existing service access token and both tested OAuth credentials all passed
   `/api/whoami-v2` and all received 429 from the gateway environment. This
   isolates a location-dependent access failure; it does not identify HF's
   internal limiting rule. No credential was printed or returned to browsers.

## Deployed repairs

- Inference and atlas retrieval request 60 seconds; chat already requested 60.
  Predictions, model weights, prompts and scientific interpretation are unchanged.
- The gateway uses `/queue/join` and `/queue/data`, preserving model errors.
- It forwards HF's signed visitor identity and sends both documented/private
  Space authorization headers only to the configured model hosts. These headers
  do not eliminate the observed platform 429.
- Cooldowns and reachability caches are scoped to visitor identity and bounded.
- Explicit scheduler-duration refusal refunds the application reservation;
  accepted or ambiguous failures retain it and are not automatically resubmitted.
- Health requires sufficient application budget for every supported operation.
  The ledger is explicitly distinguished from HF's live quota and billing.
- Temporary credential diagnostics and their temporary secret were removed.

## Verification

- 59 gateway regression tests and 5 browser-client contract tests passed.
- A single direct authenticated inference job using the website's public RCC
  example completed on September 6 at 10:05 UTC in 22.99 seconds and returned
  50 unique ranked genes. This confirms the repaired model path, not the public
  gateway path.
- Direct spot chat returned a nonempty assistant response in 22.72 seconds;
  direct atlas retrieval returned five results and evidence in 41.31 seconds.
  Each was submitted once, without retries, completing by 10:09 UTC.
- The anonymous public integration check failed at health with both backend
  entrances returning 429. It did not mark this run successful.
- `scripts/smoke_public_gateway.py` now checks uncached inference, conversation,
  follow-up, atlas retrieval, atlas conversation and cached repeat, writing a
  successful summary only when every step passes. It consumes real allowance.

## Approved single-Space deployment

The operator approved merging the API and models. The unified Gradio process
runs in the existing ZeroGPU `wli14/HistAgent-agent` Space. The original CPU
gateway could not be changed to ZeroGPU with the available hardware-management
permission, so the website endpoint moves to the existing GPU Space. No paid
hardware or new hosting service was created.

`scripts/build_unified_space.py` builds this deployment from the canonical model
implementations. A single dispatcher serves image ranking, retrieval and chat;
the API invokes it locally without `/config`, upload or queue HTTP calls to
another Space. The application ledger, bounded cache and visitor limits remain.
HF still performs its normal GPU scheduling and visitor-quota checks.

Startup loads all three models and packs 36.4 GB of tensors. PEFT adapter weights
are deserialized on CPU before loading into the CUDA model, avoiding an eager
CUDA-access failure in ZeroGPU startup. Model identifiers, precision, scientific
prompts and inference code remain unchanged. The 50 public-example ranked genes
match the original standalone result in exactly the same order. The shared
dispatcher requests 30 seconds after preloading; the deployed Blackwell scheduler
scales that to 45 seconds. Measured example model execution took 0.79 seconds for
image ranking, 1.47 seconds for retrieval, and approximately 3–4 seconds for chat.

Model download credentials and the long-term private-ledger credential remain
separate. A one-time credential-transfer helper was removed after successful
transfer; no credentials were exposed to website code or logs. Corrupt images
are rejected before GPU-budget reservation. Known scheduler refusals, including
Gradio HTML error subclasses, refund unused reservations.

## Remaining platform quota constraint

Anonymous image generation, chat and follow-up each completed with HTTP 200.
The next uncached request was refused by HF's separate execution-count limit.
The actual scheduler error was classified as `runs`, not a GPU-duration shortage
or an HTTP edge failure. Reducing the requested duration did not remove that
run-count rejection. Restarting a Space does not reset a visitor's platform quota.

An owner's PRO allowance does not automatically fund anonymous incoming requests.
The documented way to use that account allowance is an authenticated request
at the HF entrance. Complete account-funded checks use `--hf-auth`, record their
authentication mode, and send the local Hub token only to a configured HistAgent
HF API endpoint. Website image requests receive no credential. These checks must
not be reported as an unlimited anonymous-access guarantee.

The website now preserves the platform's daily-run-limit explanation and does
not confuse its internal five-minute retry cooldown with a quota reset time.
Atlas chat labels its local evidence summary when live chat cannot execute.

During validation, HF served the previous healthy container while the next
revision was `RUNNING_APP_STARTING`. This caused one expected cache miss across
the container replacement. Two identical requests after the final container
became stable both hit the cache. Wait for the target revision to reach `RUNNING`
before starting a fresh release smoke test.
