# Public workbench access incident — 14 November 2026

## Confirmed

The published frontend calls `https://wli14-histagent-api.hf.space`. Fresh anonymous GETs to `/api/health` at that host and `https://wli14-histagent-agent.hf.space`, with the correct website Origin `https://histagent.bio`, return Hugging Face HTML 404 rather than application JSON. Browser preflight to `/api/generate` still returns 200; a successful preflight therefore does not establish application availability. The browser chat field is intentionally disabled until image inference produces evidence, so an unavailable backend prevents that field becoming usable.

Neither wli14 Space is visible through public Space listing or the current account's Space metadata requests. The wli14 account and its public LoRA and atlas-image repositories still exist. It is not established whether these Spaces were deleted, renamed, or made private.

Current CLI ownership is wli13 on the free account tier. Its existing public `HistAgent-demo` and `HistAgent-chat` Spaces are SLEEPING with requested hardware `zero-a10g`. Each has zero server secret names and zero variables. Their deployed applications are the older July implementations; the demo still requests 180 seconds and the chat implementation loads plain Qwen without the released PEFT adapter. Redirecting the website to these old runtimes would not preserve the current scientific service.

The current account can read the public HistAgent checkpoint, released LoRA, atlas images, and data repositories. An authenticated HEAD request to the gated GigaPath `pytorch_model.bin` succeeds. Both public evidence-bank release files (embedding and metadata) succeed on anonymous HEAD requests. No GPU job was submitted during this diagnosis.

## Exact authentication blocker

The only locally available Hub credential is temporary OAuth, not a durable production service token. Neither existing wli13 Space contains a server-side credential. The canonical unified app refuses startup without its private-ledger service credential, and the wli14 quota-ledger dataset is inaccessible to the current account. The existing owner proxy additionally hardcodes the wli14 owner identity, token-secret name and upstream hostname. Reusing it under wli13 requires explicit owner/upstream configuration and a durable server credential; changing only the frontend hostname is insufficient. No token value was copied, printed, or placed in this repository.

Repo write and hardware-management permission have not been proven by read-only inspection; account ownership and runtime metadata alone are not proof of those capabilities.

## Required next step

Preferred: regain management access to the original wli14 Spaces and restore their existing public API and unified model deployment, preserving service credentials and quota ledger.

Alternative without new paid compute: use the two existing wli13 Spaces for the canonical merged model runtime and CPU owner proxy after a durable, appropriately scoped service token and owned private quota ledger are configured. Preserve model identifiers, adapter, image processing, evidence source, conservative budget, concurrency and no-automatic-retry behavior. Do not deploy the temporary local OAuth token as a durable service secret. Update proxy owner/upstream settings deliberately; change frontend endpoint only after the complete anonymous fresh inference, spot chat, follow-up, retrieval and Atlas-chat smoke check passes.

Current [official ZeroGPU documentation](https://huggingface.co/docs/hub/spaces-zerogpu) permits two ZeroGPU Spaces for qualifying free personal accounts. It describes five included daily GPU minutes for free accounts and two for unauthenticated visitors. Therefore free hosting is not by itself a PRO-only blocker, but owner-funded availability would share the owner's limited allowance. No upgrade or new paid resource was requested or performed.

Machine-readable endpoint, runtime and secret-count evidence is saved outside this source checkout at `output/histagent-public-access-20261114/diagnostics.json` in the revision workspace.

## Frontend mitigation

The Figure 2 original emblem has been published and verified byte-for-byte. Startup availability probes now distinguish a real live service from the manuscript example. Anonymous requests have finite deadlines, network/HTML 404 failures receive actionable messages, and failed requests are not automatically resubmitted. Image upload and spot selection remain usable; conversation still requires successfully generated evidence. Thirty-nine client/state regression tests pass, including initial image-load ordering. The old endpoint is deliberately unchanged until a replacement passes real anonymous inference and chat; this patch does not claim the model service has been restored.
